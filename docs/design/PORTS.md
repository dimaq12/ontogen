# PORTS — transport as a configurable, native functor (D88)

## The problem it dissolves

The organism's semantics are transport-agnostic — `handle(event) -> outcome`
is pure; the truth is the event log and its fold. HTTP was only the cheapest
UNIVERSAL harness (one judge, one surface for every genome), so it leaked into
the judge and the default skeletons. That is a refactor debt, not an
architectural limit: the brain never knew HTTP, exactly as it never knows Go
(invariant I1).

## The one law (already in the engine)

> The FOLD is the invariant; every transport is a FUNCTOR that must preserve
> it. Certificate = fold-parity — the same gate that certifies dialects
> (`growdialect`) and migrations (D48) — plus round-trip(encode∘decode).

A port is a `(decode, encode, driver)` triple. Two observation channels, both
native to the organism:

- **pull** — `state`/`query` -> SYNC beasts (HTTP, gRPC request-response);
- **push** — emitted events (D54) -> ASYNC beasts (queue, Kafka, MQTT).

Sync vs async is nothing but pull vs push over the SAME fold. Because the fold
is the single source of truth, ONE organism exposes MANY ports at once — each
is a projection of one fold, so they are mutually consistent BY CONSTRUCTION.

## Open-ended, not hardcoded (1..∞ beasts)

You ship the LAW + the parity gate + the growth loop, never a list. Any adapter
satisfying fold-parity and round-trip is a valid port; the set of ports is
GENERATED by the law. A new beast (gRPC, a specific broker) is a grown adapter
certified against the gate — the same loop as `growdialect`/`growisland`.

## Untrusted delivery = the membrane

A beast may drop, reorder, or double-deliver. That is the membrane doctrine
applied to the port: delivery stats (delivered/failed/retries) with assumptions
-> drift -> REVOKE (`port_trust_revoked` in the ledger). Duplicates are already
neutralised by `retry_window`; ordering/at-least-once are declared assumptions.
Retries + backoff are a first-class port policy (web/async delivery with retries).

## Where it lives

Ports are DECLARED next to the genome in `ports.yaml` — never in the frozen IR
(D72). Transport is a surface, not semantics, so it does not belong in the
genome at all. `onto serve <genome> --ports ports.yaml` starts every declared
port over one organism.

```yaml
ports:
  - {name: api,     kind: http,  direction: in,  bind: "127.0.0.1:8090"}   # sync/pull
  - {name: events,  kind: queue, direction: in,  topic: "orders"}          # async in
  - {name: shipped, kind: queue, direction: out, on: [Shipped], to: "shipped",
     retries: 3, quota: 5}                                                  # async out + retries
  - {name: hook,    kind: http,  direction: out, on: [InvoiceIssued],
     to: "https://downstream/webhook", retries: 5}                          # web out + retries
```

## Status

Built (D88, exam `fports`): the Port axis, the `http` reference port (sync/pull
+ web-out with retries), the `queue` async port (in/out with retries + membrane
REVOKE), the in-process `Bus` (a dependency-free stand-in for a real broker),
and the fold-parity law-gate. `fports` proves: byte-identical fold across
HTTP-in and async queue-in; native async out; many ports over one fold;
retries; REVOKE. GROWN codecs (D89, exam `fgrowport`): `growport` grows a port's wire codec
(decode/encode) from an intent+cases spec, certified by round-trip +
fold-parity — the transport tissue joins the same doctrine as dialects
(`growdialect`) and islands (`growisland`). Proven offline on the in-process
Bus (qwen grew an envelope codec on the first attempt); a real Kafka/gRPC
adapter is the same grown codec behind a driver swap at deploy — the
dependency lives in the door, not the brain. Open-ended, 1..inf.
