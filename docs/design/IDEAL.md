# IDEAL: the jump v1 -> v_ideal (fixed 2026-08-26)

The user's goal: **a description -> a full-fledged piece of software**. Any
domain, any language. Refinement of the aim (conversation 08-26):

## Division of labor by model strength
- **Input and syntax (NL -> genome)** — CAPABLE models (Sonnet-class):
  understanding a description and writing a genome is already within their reach,
  and it's cheap. We don't fight for weak models where strong ones cost pennies.
- **Weak models + rails** — where the volume of work is large and the gates are
  strong (intelligence in the gates, the model as an enzyme):

## The three jewels of the jump (the user's priority)
1. **(3) THE FULL PRODUCT** from the genome: queries/read-models, time, auth,
   UI-admin, deploy — the UNIVERSAL program U1-U8 (MODEL.md §7).
2. **(4) THE MODEL GROWS ISLANDS**: an island = code behind a membrane with
   assumptions — meaning an SLM can write it: the gates = drift monitors +
   assumption-Expr + retries; the human merely accepts. A manual island is the
   exception, not the norm.
3. **(5) DIALECTS ARE GROWN**: a dialect already has full gates
   (conformance corpus, golden, ONE judge across all substrates) — meaning a new
   language can be grown by the model in a CEGIS loop against those gates.
   "Any language" becomes a property of the system, not our labor.
   The v0 form of this idea: the SLM translates the CANONICAL phenotype (python)
   into the target language per-genome; the judge + fold parity certify the
   artifact (like a skill: the oracle = the canonical phenotype). Determinism —
   through a cache by genome hash + certification, not through model determinism.
